- Public Gateway: src/local_gitlab_gateway/public_gateway/main.py。
- Private Bridge: src/local_gitlab_gateway/private_bridge/main.py。
- 共通処理: common/config.py、common/middleware/{api_key,request_id,utf8_json}.py 等。
- 構築例: config/、deploy/nginx/、deploy/systemd/、deploy/wireguard/。
- 仕様: docs/ja-JP/01_仕様/01〜06、HLDocS正規化方針。

## 4. 実装状況（静的確認）

- Public Gateway で確認したルート: GET /health、GET /v1/config-check、GET /v1/gitlab/projects、GET /v1/gitlab/projects/{project_id}/repository/tree、GET /v1/gitlab/projects/{project_id}/repository/files/{file_path:path}。
- Private Bridge で確認したルート: GET /internal/health、GET /internal/config-check、GET /internal/gitlab/version、GET /internal/gitlab/projects、GET /internal/gitlab/projects/{project_id}/repository/tree、GET /internal/gitlab/projects/{project_id}/repository/files/{file_path:path}。
- branches、commits のクライアントモジュールは存在するが、両 main.py には対応するAPIルートが無い。
- File Create / Update、Merge Request Create、Issue Create のAPIルートは両 main.py で確認できない。
- Public API Key と内部 API Key の検証ミドルウェアが存在する。ヘルスチェックは認証例外。
- X-Request-ID を生成・応答ヘッダーに付けるミドルウェアはあるが、確認した public_gateway/private_bridge_client.py および private_bridge_repository_file.py の内部HTTPリクエストには request_id ヘッダー引き継ぎがない。
- public_gateway/private_bridge_client.py で内部アクセス先への httpx 呼び出しは存在するが、可観測性・監査ログ要件が充足しているかは未検証。
- private_bridge/gitlab_client.py の fetch_gitlab_version() は httpx.AsyncClient(verify=False) を指定している。TLS検証ポリシーとの整合確認が必要。
- config/public_gateway/config.example.yaml は private_bridge.base_url=http://10.20.30.2:8081 を例示。WireGuard内部区間の暗号化とアプリケーション層TLSの適用範囲を整理する必要がある。
- 実行環境のYAMLに依存した module import 時の設定ロードがある。テスト時の設定差し替えが可能か要確認。
- pyproject.toml で pytest の coverage fail-under=100 を宣言するが、tests/ はツリーに存在せずテスト実行証跡は未確認。
