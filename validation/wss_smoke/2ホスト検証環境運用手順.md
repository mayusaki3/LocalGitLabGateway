# 2ホスト検証環境 運用手順（LC-11〜LC-13）

## 目的と適用範囲

WindowsホストとHyper-V Ubuntu VMで、Public Gateway／Private Bridge／Mock GitLab／手動起動WSS Workerの結合検証環境を再現する。**本書はローカル検証用**であり、インターネット公開・本番認証設定の手順ではない。

- Ubuntu: Public Gateway、`192.168.1.191:8443`
- Windows: Private Bridge `127.0.0.1:8081`、Mock GitLab `127.0.0.1:8090`、WSS Worker
- WindowsからUbuntuへアウトバウンドWSS接続する。UbuntuからWindowsの8081/8090を公開しない。
- IPはLC-12/13の実測値。変更時は証明書SAN、Worker URL、curl URLを合わせて変更する。

## ローカルファイル

| ホスト | パス | 用途 |
| --- | --- | --- |
| Ubuntu | `~/lgg-validation/public.yaml` | Public Gateway検証設定 |
| Ubuntu | `~/lgg-validation/certs/ubuntu.pem` | TLS公開証明書 |
| Ubuntu | `~/lgg-validation/certs/ubuntu-key.pem` | TLS秘密鍵（Ubuntu外へ配布しない） |
| Windows | `validation/local-config/private.yaml` | Private Bridge検証設定 |
| Windows | `validation/local-certs/ubuntu.pem` | Ubuntu TLS公開証明書（信頼用） |

Windowsの上記2ディレクトリは`.gitignore`対象。**既にGit追跡済みのファイルには.gitignoreは効かない**ので、追跡状態は別途確認すること。トークン、PAT、秘密鍵、個人環境の値をコミット・ログ公開しない。

## 前提確認

- Ubuntu、Windows双方のリポジトリは`develop`の必要な変更を取り込み済み。
- Python仮想環境を作成済み。Windowsでは**各PowerShellごと**に`.venv\Scripts\Activate.ps1`を実行する。
- Ubuntu証明書は`192.168.1.191`をIP SANに含み、期限内であること。Windowsには公開証明書のみ配布する。
- Ubuntu側でTCP 8443への到達を許可する。Private Bridge/Mock GitLabはWindowsのloopbackのみで待ち受ける。
- 検証用認証情報がPublic/Private/Worker間で整合すること。値を本書へ記載しない。

## 起動順

### 1. Ubuntu: Public Gateway

```bash
cd ~/work/LocalGitLabGateway
source .venv/bin/activate
export LGG_PUBLIC_CONFIG="$HOME/lgg-validation/public.yaml"
python -m uvicorn local_gitlab_gateway.public_gateway.main:app \
  --host 0.0.0.0 --port 8443 \
  --ssl-certfile "$HOME/lgg-validation/certs/ubuntu.pem" \
  --ssl-keyfile "$HOME/lgg-validation/certs/ubuntu-key.pem"
```

### 2. Windows: Mock GitLab（専用PowerShell）

```powershell
Set-Location "D:\WORKPLACE\M1SH\DEV\GitHub\LocalGitLabGateway"
.\.venv\Scripts\Activate.ps1
python -m uvicorn validation.wss_smoke.mock_gitlab:app --host 127.0.0.1 --port 8090
```

### 3. Windows: Private Bridge（別PowerShell）

```powershell
Set-Location "D:\WORKPLACE\M1SH\DEV\GitHub\LocalGitLabGateway"
.\.venv\Scripts\Activate.ps1
$env:LGG_PRIVATE_CONFIG = (Resolve-Path ".\validation\local-config\private.yaml").Path
python -m uvicorn local_gitlab_gateway.private_bridge.main:app --host 127.0.0.1 --port 8081
```

### 4. Windows: WSS Worker（別PowerShell、**手動起動のみ**）

```powershell
Set-Location "D:\WORKPLACE\M1SH\DEV\GitHub\LocalGitLabGateway"
.\.venv\Scripts\Activate.ps1
$env:LGG_TUNNEL_WSS_URL = "wss://192.168.1.191:8443/internal/tunnel/v1"
$env:LGG_TUNNEL_TOKEN = "<検証用トンネルトークン>"
$env:LGG_PRIVATE_BRIDGE_URL = "http://127.0.0.1:8081"
$env:LGG_INTERNAL_API_KEY = "<検証用内部APIキー>"
$env:SSL_CERT_FILE = (Resolve-Path ".\validation\local-certs\ubuntu.pem").Path
python -m local_gitlab_gateway.private_bridge.tunnel_worker
```

`<...>`は実際の検証用設定と一致する値に置換する。Workerの自動起動やOSサービス化は行わない。

## 稼働確認

Windowsの別PowerShellで実施。

```powershell
Test-NetConnection -ComputerName 192.168.1.191 -Port 8443

Get-NetTCPConnection -State Listen |
  Where-Object { $_.LocalPort -in @(8081, 8090) } |
  Select-Object LocalAddress, LocalPort, OwningProcess

Get-NetTCPConnection -RemoteAddress 192.168.1.191 -RemotePort 8443 -ErrorAction SilentlyContinue |
  Select-Object LocalPort, State, OwningProcess

curl.exe --cacert ".\validation\local-certs\ubuntu.pem" -i `
  -H "Authorization: Bearer <検証用公開APIキー>" `
  "https://192.168.1.191:8443/api/v1/projects?page=2&per_page=5"
```

期待結果：TCP 8443到達可能、8081/8090は`127.0.0.1`待受、WorkerのTCP接続は`Established`、APIはHTTP 200とMock GitLab `id=42`を返す。Worker未接続時はHTTP 503 `tunnel_unavailable`。

## 正常停止

1. 新規API要求を止め、処理中の要求の完了を待つ。
2. **Windows Worker**のターミナルで`Ctrl+C`。必要に応じてAPIが503になることを確認する。
3. Windows Private BridgeとMock GitLabの各ターミナルで`Ctrl+C`。
4. Ubuntu Public Gatewayのターミナルで`Ctrl+C`。
5. LC-13の一時ファイアウォール規則が残っていないことを確認する。

```powershell
Get-NetFirewallRule -Name "LGG-LC13-Block-Ubuntu-WSS" -ErrorAction SilentlyContinue
```

残っている場合のみ、管理者PowerShellで`Remove-NetFirewallRule -Name "LGG-LC13-Block-Ubuntu-WSS"`を実行する。

## 障害対応

| 症状 | 確認・対処 |
| --- | --- |
| Ubuntu TCP 8443に到達しない | VM起動状態、Public Gatewayプロセス、IP変更、Firewall規則を確認 |
| TLS証明書エラー | 証明書の有効期限・IP SAN・Windows側公開証明書の一致を確認。証明書検証は無効化しない |
| API 503 `tunnel_unavailable` | Worker起動状態、WSS URL、認証設定、ネットワークを確認 |
| API 502 | Private Bridge、Mock GitLabの起動状態とそれぞれのログを確認 |
| 一時的な8443遮断から復帰しない | 遮断規則を解除し、TCP到達・Worker接続・API応答を順に確認。Workerをすぐ再起動せず再接続ログを保全 |
| Windows/VM再起動後に起動しない | 各サービスとWorkerは自動起動しない。永続保存した設定・証明書を確認し、起動順に従って再開 |
